## What changed since 2025-11-25 (changelog page)

- The protocol is stateless. The `initialize` / `notifications/initialized` handshake
  is gone. Every request carries its protocol version and client capabilities in
  `params._meta` (SEP-2575).
- `ping`, `logging/setLevel` and `notifications/roots/list_changed` are removed.
  Logging, Roots and Sampling are Deprecated (SEP-2577); stdio servers log to stderr.
- Servers **MUST** implement `server/discover`.
- Every result carries a required `resultType` (`"complete"` for ordinary results).
  Clients treat results that omit it as complete, so legacy results stay readable.
- `tools/list` (and the other list/read results) carry `ttlMs` and `cacheScope`
  (SEP-2549). Tools SHOULD come back in a deterministic order.
- MCP error sub-range: -32020..-32099 is reserved for the spec.
  `UnsupportedProtocolVersion` is **-32022**.
- `inputSchema` / `outputSchema` accept any JSON Schema 2020-12 keywords;
  `structuredContent` may be any JSON value (SEP-2106).

## Per-request metadata (basic overview page)

| `_meta` key | Required | Notes |
|---|---|---|
| `io.modelcontextprotocol/protocolVersion` | yes | version this request speaks |
| `io.modelcontextprotocol/clientCapabilities` | yes | may be `{}` |
| `io.modelcontextprotocol/clientInfo` | SHOULD | name + version |
| `io.modelcontextprotocol/logLevel` | no | Logging is deprecated |

"A request missing any required field is malformed; the server MUST reject it with
JSON-RPC error code -32602 (Invalid params)." Servers SHOULD put
`io.modelcontextprotocol/serverInfo` in each result's `_meta`.

## Version negotiation (versioning page)

No handshake. An unsupported version gets:

```json
{"code":-32022,"message":"Unsupported protocol version","data":{"supported":["2026-07-28","2025-11-25"],"requested":"1900-01-01"}}
```

Eras: *modern* = 2026-07-28 and later (per-request `_meta`); *legacy* = 2025-11-25 and
earlier (`initialize`); *dual-era* = both. A dual-era server picks behavior from how the
client opens: a request carrying modern `_meta` is served statelessly; an
`initialize` request selects legacy semantics for that stdio process. Both may be served
by the same process.

## server/discover (discovery page)

Result: `resultType`, `supportedVersions`, `capabilities`, `_meta.serverInfo`,
optional `instructions`, and `ttlMs` + `cacheScope` ("This operation supports
caching").

## stdio binding (transports/stdio page)

- One JSON-RPC message per line, UTF-8, **no embedded newlines**.
- stdout carries only MCP messages; stderr is free-form logging and not an error signal.
- The server never writes JSON-RPC requests.
- Cancellation: `notifications/cancelled` with the request id; stop work, send nothing more.
- Shutdown: the server SHOULD exit promptly on stdin EOF. On Windows the client uses
  TerminateProcess or Job Objects, so EOF handling is the only portable graceful path.
- Legacy probe: a dual-era client sends `server/discover` first and falls back to
  `initialize` on any non-modern error.

## Tools page

- Capability `{"tools":{}}` (`listChanged` only if list-changed is emitted; it is not).
- `tools/list` result: `resultType`, `tools[]`, optional `nextCursor`, `ttlMs`,
  `cacheScope`. Must not vary per connection.
- Tool: `name` ([A-Za-z0-9_.-], 1..128), optional `title`, `description`,
  `inputSchema` (object schema), optional `outputSchema`, `annotations` (untrusted
  hints such as `readOnlyHint`).
- `tools/call` result: `resultType`, `content[]`, optional `structuredContent`,
  `isError`. Tool execution failures are results with `isError: true`; protocol
  problems (unknown tool, malformed params) are JSON-RPC errors.

## Consequence for this unit

Current hosts (Codex, Claude Code) are expected to still open with `initialize` on a
legacy revision, while spec-current clients send `_meta` and may probe with
`server/discover`. The server is therefore **dual-era**: 2026-07-28 served statelessly,
legacy revisions answered through `initialize`. Which era a given host actually uses is
observed in wp3's registration smoke, not assumed.
